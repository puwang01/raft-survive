# 06 — Godot 项目结构建议

## 为何 2D 优先

- 移动端性能余量更大，热更新与包体更易控制。
- 钩子抛物线、漂流物、筏格网格在 2D（或 2.5D 微俯视）下规则清晰，适合「短关卡 + 紧张 UI」。
- 美术管线可用精灵 / 瓦片，迭代快于全 3D。
- 若日后需要微仰视立体感，可在 2D 中用分层视差或有限 3D 套娃，而不先锁死全 3D 架构。

（最终 2D vs 微仰视见 07。）

## 建议目录（Godot 4）

```
res://
├── project.godot
├── addons/                 # 可选插件
├── assets/
│   ├── art/
│   ├── audio/
│   └── fonts/
├── scenes/
│   ├── boot/               # 启动、版号、闪屏
│   ├── meta/               # 主菜单、关卡选择、设置、存档界面
│   ├── level/              # 关卡根场景、天气、生成器
│   ├── raft/               # 木筏、甲板格、玩家
│   ├── hook/               # 钩子、轨迹预览
│   ├── items/              # 漂流物、拾取物
│   └── ui/                 # HUD、暂停、建造面板
├── scripts/
│   ├── systems/            # 生存值、存档、音频、震动
│   ├── data/               # Resource 定义：物品、配方、关卡配置
│   └── util/
├── resources/              # .tres 关卡表、物品表
└── saves/                  # 开发期本地存档示例（发布时用 user://）
```

## 场景拆分要点

| 场景 | 职责 |
|------|------|
| `LevelRoot` | 组装海面、生成器、天气、胜负判定 |
| `Raft` | 网格化甲板；承受建造/破坏 |
| `Player` | 站位、动画；不直接处理存档 |
| `HookController` | 输入 → 抛物线 → 抓取 → 拉回 |
| `SurvivalSystem` | 三维数值 tick；发信号给 UI |
| `SaveService` | 自动/手动存读；原子写；后台暂停钩子 |
| `HUD` | 只显示，不写游戏规则 |

用 **信号 / EventBus** 解耦：例如 `SurvivalSystem.thirst_changed` → HUD；`HookController.loot_retrieved` → Inventory。

## 数据驱动

- 关卡用 `LevelConfig` Resource：时限、目标、刷怪/刷物表、天气曲线。
- 物品与配方用表驱动，避免硬编码在场景里。

## 实现优先级（建议）

1. **垂直切片**：单关 + 抛钩打捞浮木 + 三维生存条 + 胜负
2. **存档**：手动 + 60s 自动 + 进后台强制存
3. **建造最小集**：铺木板扩 1～2 格
4. **关卡 2～3**：风暴或口渴压力
5. **iPad 布局适配** 与设置项（自动存档间隔）
6. 鲨鱼 / 信号胜利等后期内容

## 导出与输入

- 项目设置启用移动触控；鼠标点击映射为触控以便桌面调试。
- 及早在真机测：抛钩手感、热区、进后台存档。
