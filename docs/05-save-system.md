# 05 — 存档系统

## 目标

在移动端提供**可靠、省电、少卡顿**的存档体验：

- 允许**手动存档**
- 支持**自动存档**，间隔可选 **30 秒** 或 **60 秒**
- **默认建议：60 秒**；设置中可改为 30 秒（避免移动端频繁 I/O）

## 手动存档

- 入口：暂停菜单 →「保存进度」
- 行为：写入当前选中槽位（或弹出槽位选择）
- 成功：Toast「已保存」+ 时间戳
- 失败：明确错误提示（磁盘满、权限等），不静默失败

## 自动存档

| 选项 | 间隔 | 适用 |
|------|------|------|
| **推荐默认** | **60 秒** | 平衡安全与闪存寿命 / 卡顿 |
| 可选设置 | 30 秒 | 玩家更怕掉进度时自行开启 |
| 也可提供 | 关闭自动存档 | 仅手动（需二次确认） |

额外触发（不论间隔）：

- 进入后台 / 收到 `NOTIFICATION_APPLICATION_PAUSED`（或等价）时 **强制存一次**
- 关卡胜利结算前强制存 meta 进度
- 手动存档后重置自动存档计时，避免连写

## 存什么

单槽存档建议覆盖：

| 字段类别 | 内容示例 |
|----------|----------|
| 筏布局 | 各甲板格类型、耐久、相对坐标 |
| 库存 | 物品 id、数量、快捷栏 |
| 三维生存值 | Health / Hunger / Thirst（及短时 buff） |
| 关卡进度 | 关卡 id、主目标计数、阶段、剩余时限 |
| 世界状态 | 游戏内时间、天气、随机种子（便于威胁节奏一致） |
| Meta | 已解锁关卡、设置（含自动存档间隔）、槽位说明 |

体积控制：优先 JSON / 二进制紧凑格式；避免存整帧场景树。

## 槽位

- 首版建议 **3 个手动槽** + **1 个自动槽**（自动槽可只读展示「最近自动保存」）。
- 读档界面显示：关卡名、时间戳、生存三维摘要、筏格数。

## 移动端写入策略

1. **原子写**：先写临时文件 → `flush` → 重命名替换正式档，防止杀进程导致坏档。
2. **主线程友好**：序列化可在主线程做（数据量小）；写入文件尽量短；必要时用 Worker / 后台线程写盘，完成后再切换「正式档指针」。
3. **后台暂停强制存**：进后台、来电、系统杀进程前尽可能落盘。
4. **节流**：30s 档也要合并「暂停强制存」与「到达间隔」的重复写。
5. **校验**：读档时校验版本号与简单 checksum；失败则回退上一份 `.bak`（若有）。

## 设置文案建议（中文）

- 自动存档：`关闭 / 每 30 秒 / 每 60 秒（推荐）`
- 说明小字：`较频繁的自动存档可能略微增加设备耗电与存储写入。`

## 与短关卡的关系

即使单局只有 3～5 分钟，自动存档仍有价值：

- 玩家中途接电话 / 切应用不会丢当前关进度
- 多段章节游玩时减少挫败

若某关极短且允许任意重来，仍保留自动存档，但可读档提示「本关可快速重开」。
